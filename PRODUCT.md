# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

People exploring a simulated digital wallet, and reviewers evaluating this educational full-stack portfolio project.

## Product Purpose

Make registration, a funded sandbox wallet, internal transfers and transaction history usable while demonstrating financial consistency, authorization and reproducible tests.

## Operating Context

Local development first. A user creates an account, receives fictitious USD funds, and transfers to another registered user's email. No bank account or real payment information is needed.

## Capabilities and Constraints

The approved scope is the master document narrowed by ADR-000 and ADR-001. One USD wallet per user. Every balance change has a balanced ledger origin. Access tokens stay in memory, refresh tokens in HttpOnly cookies. Risk scoring, external currencies and email are deferred. Deployment accounts and public domain remain undecided.

## Brand Commitments

PayFlow; an English-language fintech interface, light surfaces, restrained navy, semantic state colors and a persistent sandbox disclaimer. Preserve the established identity in the source and master document while adding functional screens. The user authorized implementation based on the preceding analysis and asked the agent to continue with available local resources.

## Evidence on Hand

The master document, accepted architecture decisions, actual backend operations and automated tests. Never invent user activity, external certifications, customer counts or banking integrations.

## Product Principles

- Financial integrity is required from the first operation.
- Confirm recipient and amount before sending.
- Preserve the request reference when an outcome is uncertain.
- Expose real stored data and useful empty states.

## Accessibility & Inclusion

Responsive desktop and mobile web, visible keyboard focus, explicit form labels, accessible error messages and states distinguished by text as well as color.
