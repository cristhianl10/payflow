# Wallet workspace

Mode: Operate. Scope: authentication, overview, send flow, activity, wallet and account.
The user authorized implementation and a fintech UI following the analyzed project. The master document already specifies light surfaces, navy, a desktop sidebar, balance, actions and recent activity. This extends that established world; no replacement visual identity or generated imagery is needed. The direct implementation path is a session assumption while the optional visual-workflow question remains unanswered, not a saved preference.

## Direction contract

THESIS: Understand the available sandbox balance, then make one considered transfer. Financial information carries the screen; decorative analytics do not.

OWN-WORLD: Navy navigation and balance surface, cool white workspace, restrained green for received funds, clear red errors, 12px surfaces and one sans-serif family.

STORY: Sign up or sign in, read the funded wallet, select a registered recipient, review exact details, confirm, then follow the persisted receipt.

FIRST VIEWPORT: A compact left navigation, top account strip, heading, prominent balance and send action, paired with receiving instructions. Sent and received totals exclude the opening grant. A transaction table follows immediately. Mobile moves navigation above content and stacks the balance and receipt.

FORM: The dashboard and transfer review specified in the existing master document; a constrained extension of the incumbent navy/light system, so no concept seed applies. Signature interaction: review-to-receipt with preserved idempotency reference on uncertain outcomes.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
